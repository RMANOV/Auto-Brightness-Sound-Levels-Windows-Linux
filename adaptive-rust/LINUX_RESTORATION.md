# Linux restoration boundary

Linux builds use the real `v4l` YUYV webcam backend and Linux brightness/volume controls; Windows builds retain the existing solar simulation and CoreAudio/WMI architecture. The camera body is unchanged; the Windows brightness and volume modules now preserve explicit capability and command/readback errors, so their bytes are no longer identical to the original port. Linux V4L2 is a target-specific dependency. Existing microphone sampling remains 200 ms every 5 seconds; Linux camera cadence is the historical 100 ms, Windows simulation cadence remains 2 seconds. These are controller cadences, not the manager's ten-minute scheduling policy or its separate short camera probe.

Brightness binds one named `/sys/class/backlight` device. With multiple devices set `ADAPTIVE_BACKLIGHT_DEVICE` to the exact basename; missing, ambiguous or invalid names fail. Every `brightnessctl` call specifies both backlight class and device, so an LED is never an implicit default. Commands are bounded by GNU `timeout` (3 seconds with a one-second kill grace); a failed direct set may use the existing noninteractive `sudo -n /usr/bin/brightnessctl` fallback. No sudoers or device permissions are changed. Both failed commands, invalid readback, zero maximum, or mismatch return errors. A successful set requires same-device raw `get/max` readback within one raw hardware step of the clamped integer-percent request. This is actuator readback, not a photometric measurement of screen luminance.

The controller reads confirmed brightness after setting. Convergence consumes independently accumulated fresh camera and audio evidence exactly once per stability step and requires same-device finite brightness within one raw hardware step of its rounded/clamped integer-percent target, plus real volume readback matching a present finite rounded audio target. No audio sample or absent target can be counted even when brightness is available. The two capture cadences need not coincide on a poll. Actuator verification and convergence use the same comparison; a readback beyond one step still fails. Windows WMI uses its integer-percent step. The controller logs measured state. Empty polling ticks neither increment nor reset the count; fresh mismatched samples reset it, preserving the Windows two-second cadence. A disconnected required camera or audio channel returns an error after any remaining queued sample is consumed, while an ordinarily empty live channel remains a valid poll. Burst command failure propagates after cleanup instead of returning success or accepting software-only convergence. Camera frames must actually negotiate YUYV and satisfy nonempty dimensions, stride and frame-length bounds; padding/chroma are excluded. Unsupported compressed formats fail rather than being interpreted as luminance. A one-second V4L2 stream timeout and nonblocking channel delivery avoid indefinite ordinary reads/channel shutdown waits; real driver behavior and cleanup still require native validation under the manager's outer timeout.

Linux Sun boost obtains the local UTC offset for the captured timestamp using bounded `/usr/bin/date`; inability to establish it disables boost with a warning. Sofia coordinates and the core 30-minute-before/two-hour-after Sun policy remain unchanged. The manager owns the authoritative schedule and adjacent-day/zone configuration work.

The compatibility `fast_log10` entry point uses the standard f32 logarithm. The earlier truncated mantissa polynomial failed existing accuracy assertions and mishandled special/subnormal values. Curve factor, multiplier, bias, volume bounds and existing tests are preserved; there is no claimed benchmark speedup.

Offline unit tests use supplied command results, pure frame/math parsing, and temporary fake backlight directories. They do not open a camera, audio device, or real backlight. Build dependencies include cached v4l/bindgen and libclang; libclang is build-only. The private release artifact and evidence are outside the worktree. Hardware response, camera exposure/calibration, cancellation timing, full device cleanup and Windows native behavior are not established by compilation/tests.

Linux volume selection first probes the active session default sink using `pactl`, then `wpctl`, and uses ALSA `amixer Master` only if neither session method is readable. The selected backend remains pinned for writes/readback; a later failure propagates rather than switching to an unrelated sound card. Backend-valid amplified session volume (for example125%) is retained for selection/readback; configured output targets and setters keep their existing bounds. PulseAudio percent uses its rounded maximum representable volume and wpctl uses a finite nonnegative safely representable integer-percent bound. ALSA still requires0..100. See [PulseAudio volume.h](https://github.com/pulseaudio/pulseaudio/blob/master/src/pulse/volume.h) and [wpctl notes](https://pipewire.pages.freedesktop.org/wireplumber/man/wpctl.html#notes).

Windows desktops without WMI brightness explicitly report that capability unavailable. The controller does not call its brightness getter/setter, does not run the simulated camera worker for convergence, and labels brightness unavailable instead of confirming a fabricated50%. Volume-only warmup/convergence uses fresh microphone samples and actual finite volume readback matching the rounded target; empty polls or an absent target cannot count. Once WMI is available, later query/set failure remains an error. Windows volume helper HRESULTs, process status, percent parsing and set/readback mismatch also propagate errors. The checked v3 helper uses a versioned non-device self-test token, so endpoint unavailability is not treated as executable corruption. Missing or corrupt cache is compiled in an exclusively created sibling staging directory, validated with the self-test, then replaced with same-volume MoveFileExW (replace-existing, write-through); the old destination is never deleted before publication. Compile, candidate self-test or publication failure preserves the incumbent and cleans only owned staging files. Normal get/set failures remain errors, not triggers for live recompilation. Windows-only unit tests compile the actual embedded C# and execute only its self-test without accessing audio/brightness. Host tests and Windows crosscheck do not establish that native test result or real COM/device behavior.
