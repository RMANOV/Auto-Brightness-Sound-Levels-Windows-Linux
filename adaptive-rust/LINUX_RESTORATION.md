# Linux restoration boundary

Linux builds use the real `v4l` YUYV webcam backend and Linux brightness/volume controls; Windows builds retain the existing solar simulation/WMI/CoreAudio implementation in the `*_windows.rs` modules. Linux V4L2 is a target-specific dependency. Existing microphone sampling remains 200 ms every 5 seconds; Linux camera cadence is the historical 100 ms, Windows simulation cadence remains 2 seconds. These are controller cadences, not the manager's ten-minute scheduling policy or its separate short camera probe.

Brightness binds one named `/sys/class/backlight` device. With multiple devices set `ADAPTIVE_BACKLIGHT_DEVICE` to the exact basename; missing, ambiguous or invalid names fail. Every `brightnessctl` call specifies both backlight class and device, so an LED is never an implicit default. Commands are bounded by GNU `timeout` (3 seconds with a one-second kill grace); a failed direct set may use the existing noninteractive `sudo -n /usr/bin/brightnessctl` fallback. No sudoers or device permissions are changed. Both failed commands, invalid readback, zero maximum, or mismatch return errors. A successful set requires same-device raw `get/max` readback within one raw hardware step of the clamped integer-percent request. This is actuator readback, not a photometric measurement of screen luminance.

The controller reads confirmed brightness after setting, requires a fresh camera sample and actual finite brightness within one percent of target for convergence, and logs confirmed state. Empty polling ticks neither increment nor reset the count; fresh mismatched samples reset it, preserving the Windows two-second cadence. A disconnected required camera channel returns an error after any remaining queued frame is consumed, while an ordinarily empty live channel remains a valid poll. Burst command failure propagates after cleanup instead of returning success or accepting software-only convergence. Camera frames must actually negotiate YUYV and satisfy nonempty dimensions, stride and frame-length bounds; padding/chroma are excluded. Unsupported compressed formats fail rather than being interpreted as luminance. A one-second V4L2 stream timeout and nonblocking channel delivery avoid indefinite ordinary reads/channel shutdown waits; real driver behavior and cleanup still require native validation under the manager's outer timeout.

Linux Sun boost obtains the local UTC offset for the captured timestamp using bounded `/usr/bin/date`; inability to establish it disables boost with a warning. Sofia coordinates and the core 30-minute-before/two-hour-after Sun policy remain unchanged. The manager owns the authoritative schedule and adjacent-day/zone configuration work.

The compatibility `fast_log10` entry point uses the standard f32 logarithm. The earlier truncated mantissa polynomial failed existing accuracy assertions and mishandled special/subnormal values. Curve factor, multiplier, bias, volume bounds and existing tests are preserved; there is no claimed benchmark speedup.

Offline unit tests use supplied command results, pure frame/math parsing, and temporary fake backlight directories. They do not open a camera, audio device, or real backlight. Build dependencies include cached v4l/bindgen and libclang; libclang is build-only. The private release artifact and evidence are outside the worktree. Hardware response, camera exposure/calibration, cancellation timing, full device cleanup and Windows native behavior are not established by compilation/tests.
